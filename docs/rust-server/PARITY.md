## What the Rust port already does

The Rust server (`server-rs/crates/rcce-server`) is a mature standalone port. It implements:
account create/login, character create/fetch/delete, enter-world (`P_StartGame` + `P_ChangeArea`),
movement (`P_StandardUpdate` with echo), say-chat, melee combat with equipped-weapon damage +
armour mitigation, NPC death + XP + loot death-scripts, spell-casting (`P_SpellUpdate`: cooldowns,
memorise, race/class exclusivity, projectile/sound/emitter visuals), an RSL script interpreter with
~40 BVM commands, dialog (`OpenDialog`/`DialogOutput`/`DialogInput` async suspend/resume),
right-click/examine/trade hooks, player↔player trading + NPC vendor buy/sell, inventory
drop/pickup/swap/stack-merge/give-item, potions + timed `ActorEffect` buffs, warp + portal-walking
zone transitions, attribute get/set/change, gold, XP, quest/actor globals.

The gaps below are what the Blitz reference server does that the port does not yet match. The
unhandled-packet path falls to `_ => Vec::new()` (`state.rs:2381`); the unhandled-BVM path falls to
`_ => Value::Int(0)` (`scripts.rs:573`). Both fail safe — nothing crashes — so every gap below is a
silent no-op, not an error.

There is **no "Blocks play" item** under the current north star (a standalone Rust client ↔ Rust
server stack). The two packets that would block a _stock Blitz client_ (`P_FetchActors`,
`P_FetchUpdateFiles`) are listed under Gameplay with that conditional called out, because the Rust
client loads catalogs locally and never sends them.

## Recommended implementation order

Grouped so overlapping code areas are batched. The first three items are the highest-value, lowest-risk, and several later items depend on the NPC-AI tick loop.

1. **BVM_SETACTORGLOBAL privilege gate** (`scripts.rs:384`) — security fix, tiny, isolated; close the cross-player quest-flag injection first.
2. **Persist live player position + current area across logout** (`world.rs`/`state.rs` disconnect+autosave) — every walking player currently loses their location on relog; small, self-contained writeback. Fold in the **LastPortal triad** persist while in this code.
3. **NPC respawn + spawn-frequency timer** (`spawn.rs`) — stops zones depleting over a session; self-contained counter + tick re-check.
4. **NPC chase movement + range-gated swing** (`state.rs:2168` + `spawn.rs`) — fixes zone-wide retaliation hits; establishes the per-tick NPC movement step.
5. **Energy drain while running** (new per-tick movement step) — batch with #4 since both add the movement/tick step; introduces the player movement-economy loop that mount/underwater reuse.
6. **NPC aggro-on-sight + AICallForHelp** (`spawn.rs` scan, faction ratings) — builds on #4's movement; pairs with the faction read-fields the BVM faction mutators also need.
7. **Quest mutators (NEWQUEST/UPDATE/COMPLETE/DELETE)** + `P_QuestLog` encoder (`scripts.rs` + `world.rs`) — unlocks quest-giver content; batch with **GIVEXP/GIVEKILLXP/SETACTORLEVEL** and **SETGOLD/SETMONEY/CHANGEMONEY** so reward scripts become functional in one pass.
8. **BVM_SPAWN / SPAWNITEM** (`scripts.rs` → `insert_npc` / item drop) — promotes the existing test-only `insert_npc` to production; enables scripted encounters and quest drops.
9. **P_ItemScript (=43)** dispatch arm (`state.rs` + script host) — non-consumable item use; reuses the right-click/trade script-hook plumbing.
10. **Spell memorisation 6s delay** (`state.rs:2115` + tick loop) — `RequireMemorise` is ON in the shipped config, so this is live; needs a pending-record + tick-commit step.
11. **P_ScriptInput (=53) + P_ProgressBar (=51)** resume arms (`state.rs`) — batch together: both resume a suspended `ScriptInstance` exactly like `handle_dialog_response`.
12. **P_ChatMessage slash-command dispatch** (`world.rs:619` → BVM command table) — unblocks admin/`In-game Commands`; depends on enough BVM mutators (#7–#8) existing to be useful.
