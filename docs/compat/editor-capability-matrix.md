- **Status:** discovery baseline; no replacement disposition or retirement claim in this file is yet accepted

## How to read this matrix

This document records three different things without treating one as proof of another:

1. **Current evidence** describes what source or a bundled artifact exposes now.
2. **Replacement routing** names the implementation packets that must decide and prove the successor disposition. A route is not a parity claim.
3. **Retirement evidence** states the concrete proof that must exist before an application can cease to be required.

Evidence labels have the following meanings:

| Label | Meaning |
|---|---|
| **Inspected source** | The behavior is present in repository source at the cited location. |
| **Inspected artifact** | A bundled document, template, archive member, or static executable/JAR string supports the claim; source is unavailable. |
| **Inferred** | A consequence follows from inspected evidence but was not exercised. |
| **Unknown** | Static evidence is insufficient. Unknown is an evidence state, not a promise that the successor will reproduce the behavior. |

No application was launched and no project or external database was mutated for this census. Source-absent applications therefore remain artifact-backed or Unknown; their cells do not establish runtime parity, encoding, overwrite, recovery, authentication, or transaction behavior.

## Retirement control

An application row may advance from this discovery baseline only when its routed packets attach exact fixtures, commands, results, and independent review. Final retirement requires all of the following:

1. `M10-DISPOSITIONS` records every capability cell as native, converted, intentionally unsupported, or optionally retained/delegated without being required, with owner/date. Any required retained/delegated dependency keeps the affected application-retirement gate open/red.
2. Required format rows have the accepted compatibility level; “the file parsed” is not authoring or runtime parity.
3. Rust client/server consume the exact editor-written fixtures for runtime-relevant state.
4. `M10-CLEAN-MACHINE` builds, edits, validates, plays, administers where enabled, and publishes without a preinstalled BlitzForge/C++ editor toolchain or a required legacy executable.
5. `M10-FREEZE` preserves a recoverable archive and blocks new required legacy dependencies.
6. `M10-SCORECARD` names unsupported and optionally retained/delegated rows instead of hiding them in an aggregate percentage, and reports any required retained/delegated dependency as a red/open retirement gate.
7. `M10-REMOVE` occurs only in a separately authorized, recoverable change after the preceding evidence is accepted.

Until then, this matrix is an inventory and routing control—not proof that the Rust super editor replaces any application.
