# RCCE project-format compatibility matrix

- **Packet:** `SE-M0-P01`
- **Matrix version:** `0.1.0`
- **Canonical task:** 1
- **Evidence base:** repository commit `23ef44f6a287a300c9ddfa4f5f059577a13c1347`
- **Inspected:** 2026-07-20
- **Scope:** durable files inside an RCCE project, project-adjacent editor state, runtime-private state, and generated project-root projections

## Purpose and interpretation

This is the evidence baseline for the Rust super editor. It records the formats that an existing project can contain without implying that every file is safe to edit. A row is a distinct identity, layout, ownership, or persistence contract. Files with the same extension remain separate rows when their contracts differ.

Compatibility is the current **Rust successor** capability, not the legacy editors' capability:

| Level | Meaning in this matrix |
|---|---|
| `I0 Inventory` | The family is known or discovered, but Rust must treat its bytes as opaque. |
| `I1 Read` | A Rust consumer parses some or all known fields. This does not prove lossless retention, strict validation, or cross-consumer consensus. |
| `I2 Lossless` | An unchanged parse/write is byte-identical, including unknown topology and bytes. |
| `I3 Semantic write` | Bounded semantic changes preserve every unrelated byte and invariant. |
| `I4 Convert` | A versioned, tested conversion contract exists. |

No row currently qualifies for `I2`, `I3`, or `I4` as an editor document. Rust runtime writers for accounts/characters are not general legacy-project writers.

Operation notation is `R` read, `W` write existing semantic state, `C` create/allocate, `D` delete/deallocate, and `N` rename persisted identity. `—` means no active source-backed operation was found. “Legacy” names the current owner; “Rust” names inspected code, not a future assignment. Fixture notation is `D` checked-in default-project example and `S` synthetic/unit fixture. Every `D` remains an unsanitized development sample, not an approved compatibility corpus fixture; “no I2” means no byte-preserving round-trip proof exists.

State classes are the program classes: `PublicClient`, `ServerConfig`, `Secret`, `DynamicPrivate`, `EditorMetadata`, `AuthoringSource`, and `Unknown`. A slash indicates that one family spans distinct authorities that a later inventory must separate by path.

Compatibility level and support disposition are orthogonal. The versioned disposition vocabulary is `undecided`, `supported-target`, and `unsupported-with-reason(reason, evidence, approval)`. At matrix version `0.1.0`, every row defaults to `undecided`; no family has yet received the evidence and approval needed to assign `unsupported-with-reason`. An `I0` row is therefore not implicitly unsupported, and a future unsupported disposition will not erase its inventory or preservation obligations.

## Media, particles, UI assets, and language

All four media catalogs begin with 65,535 LE signed 32-bit absolute-offset cells (`0..65534`); `0` means an unused slot. Records are appended and may be aliased, out of order, gapped, orphaned, invalid, or unreachable. Current Rust parsers retain only successfully decoded occupied entries, so every catalog remains `I1` at best despite active legacy writers ([legacy index creation](../../src/Modules/Media.bb#L97), [Rust topology assumptions](../../client-rs/crates/rcce-data/src/catalog.rs#L1)).

## Cross-row findings that block writer work

1. **No current Rust editor-format writer exists.** `rcce-data` and the overlapping server parsers are read-oriented. Runtime account/character serializers do not establish lossless project-authoring compatibility.
2. **Media topology is not retained.** The current Rust catalog model drops raw index cells, aliases, gaps, orphans, failed occupied cells, and unreachable bytes. Media writers therefore remain blocked even though the semantic records appear simple.
3. **Sound parsing currently contradicts active legacy source.** `PF-MED-003` cannot be promoted until a real fixture proves and corrects the record layout across client, server where applicable, and editor.
4. **The emitter model drops a persisted field.** `PF-MED-006` reads through the default texture ID but does not retain it.
5. **Fixed-attribute files are related but not interchangeable.** The client file has five shorts; the server file has six and inserts Toughness. A shared type must preserve the distinction.
6. **World files are whole-document and only partially parsed in Rust.** Visual and gameplay halves, optional Terrain source, and runtime Radar/Ownership state are separate authorities. A zone is not one legacy file.
7. **Text is not automatically lossless.** Every text family needs raw encoding/BOM/newline/trailing-line provenance before edits. Display-decoded Rust `String` values are not sufficient persisted identity.
8. **Runtime and secrets share the project tree.** Accounts, MySQL credentials, remembered login data, superglobals, drops, script files, radar fog, and live environment time cannot inherit ordinary authoring, clone, diagnostic, or publication policies.
9. **Unknowns are inventory-visible and write-blocking.** The residual rows and any future unclassified path remain opaque, preserved in full-copy operations with disclosure, and excluded from outward projections by default.
