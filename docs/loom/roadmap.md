# Loom roadmap

Shipped, next, and deferred. Read this when picking what to build next.

## Shipped (alpha + beta)

- **Skeleton** — `bin/Loom.exe` builds, Project Manager launches it, themed window opens, exits cleanly. ([#292](https://github.com/RydeTec/rcce2/pull/292), merged)
- **Theme primitives** — Loom design palette + 2D drawing helpers. Everything Loom paints goes through this layer.
- **Data loading** — same loaders GUE uses, in the same order; Loom reads through the same in-memory representation.
- **Entity browser** — boot surface; six categories (Actors / Items / Spells / Zones / Factions / Animation Sets); card grid auto-fits window width.
- **Composer panel** — per-kind property pages for all six entity kinds.
- **Thread chips + back stack** — reference fields render as clickable chips; click jumps + pushes; Esc walks back.
- **Faction and animset back-references** — composer computes "members" / "used by" rosters from `Each Actor` walks. ([#296](https://github.com/RydeTec/rcce2/pull/296))
- **Editing phase 1 (free-form text)** — Spell name editable; per-tab dirty flags shared with GUE; Save button + serializer dispatch. ([#334](https://github.com/RydeTec/rcce2/pull/334))
- **Command palette (Ctrl+K)** — modal find-anywhere across all entity kinds with prefix/substring scoring, arrow-key navigation, click-or-Enter to jump. ([#335](https://github.com/RydeTec/rcce2/pull/335))
- **Search-within-category** — live filter input above the card grid; case-insensitive substring match against the current category's name field. Esc clears the filter (priority above the back-stack pop). ([#335](https://github.com/RydeTec/rcce2/pull/335))
- **Editing phase 1 (broaden)** — int / float / bool field types; ~40 editable fields across every entity kind (Actor / Item / Spell / Zone / Faction / AnimSet); Save dispatch for every kind (`SaveActors`, `SaveItems`, `SaveFactions`, `SaveAnimSets`, `ServerSaveArea`); `SetFactionName` helper added to `Actors.bb` to work around the Strict-mode global-array-write trap. ([#336](https://github.com/RydeTec/rcce2/pull/336))
- **Entity creation (+ New)** — `EntityFactory.bb` wraps the GUE constructors (`CreateActor`, `CreateItem`, `CreateSpell`, `ServerCreateArea`, `CreateAnimSet`, faction-slot-first-empty); "+ New X" button on the browser filter bar dispatches per active category, focuses the new entity for immediate editing, marks the kind dirty. Zone names auto-deduplicate via `EntityFactory_UniqueZoneName` so a new zone doesn't overwrite an existing `.dat`. ([#337](https://github.com/RydeTec/rcce2/pull/337))
- **Entity deletion + Discard + Validation Ribbon** — Delete button on the composer (two-click arm/confirm); Discard button (revert kind from disk, also arm/confirm); Validation Conscience Ribbon at the top of every Loom surface showing per-kind dirty badges (click to save), broken-reference count (Actor->Faction, Actor->AnimSet, Zone->Portal->Zone), and total entity counts. New `Ribbon.bb` module; new `DeleteX Template` helpers in `Actors.bb`/`Items.bb`/`Spells.bb`/`Animations.bb` (non-Strict, to work around the Dim-write trap). ([#338](https://github.com/RydeTec/rcce2/pull/338))
- **World Atlas** — design's #3 signature surface. Zones tab gains a Card / Atlas toggle. Atlas renders zones as nodes with portals as edges using a Fruchterman-Reingold force-directed layout derived from the portal-link graph topology. Click a node → focus that zone; layout rebuilds on zone add / delete; circular seeding avoids the all-same-position singularity. ([#339](https://github.com/RydeTec/rcce2/pull/339))
- **Reference-field editing (phase 2)** — right-click any thread chip → palette opens as a picker filtered to that chip's kind; choosing writes the new refID into the underlying field (Actor→DefaultFaction, Actor→MAnimationSet, Actor→FAnimationSet, Zone→portal target by name). Works on broken-ref chips too (so dangling references can be repaired in place). Picker mode with empty query lists every candidate of the kind (no need to type to discover the roster). ([#340](https://github.com/RydeTec/rcce2/pull/340))
- **Session Timeline Scrubber** — design's #5 signature surface. `Modules/Loom/Timeline.bb` records every in-memory mutation (edit / toggle / create / delete) into a ring buffer capped at 200 entries. Ctrl+H opens a modal showing entries newest-first with timestamp / kind / entity / field / before→after / click-to-revert (edits + toggles only; creates and deletes log but don't revert). Module-level recorder facade (`Timeline_Record*`) so Composer / EntityFactory / Palette can record without an instance ref. ([#341](https://github.com/RydeTec/rcce2/pull/341))
- **Broken-ref finder modal** — extends the Conscience Ribbon's broken-ref count from a passive number into a clickable chip. New `Modules/Loom/BrokenRefs.bb` enumerates each broken reference (Actor→Faction/AnimSet, Zone→portal-target) with diagnosis text and click-to-jump to the source entity. Capped at 250 entries so a fundamentally broken project doesn't render thousands of rows. ([#342](https://github.com/RydeTec/rcce2/pull/342))
- **Browser keyboard navigation** — arrow keys move a brass-ringed selection cursor across the active category's card grid; Enter focuses the selected card. Up/Down jumps by row width (`lastCols`), Left/Right by 1. Selection clamps on category switch. Ctrl-anything skipped so global shortcuts (Ctrl+K / Ctrl+H) don't dribble through. ([#342](https://github.com/RydeTec/rcce2/pull/342))
- **Tools tab** — new browser category exposing GUE's seven standalone editor launchers (RC Architect, Terrain / Caves / Rock / Tree Editor, Gubbin Tool, Spell Wizard). Each card shows the tool name, description, and a Launch >> hint; click `ExecFile`s the .exe with the project's `Data/` folder as CWD. Missing-binary detection paints the card with a danger-red border + "binary not built" label so the user gets immediate feedback when the partial-build trap bites. ([#343](https://github.com/RydeTec/rcce2/pull/343))
- **Recents list (Ctrl+R)** — persisted per-project list of recently-focused entities. `Modules/Loom/Recents.bb` writes to `Data/Loom/recents.txt` (via `SafeWriteOpen/Commit`); load on boot, save on shutdown. `Threads::focus` + `Threads::jump` emit through a `Recents_Record` facade. Stable keys per kind (refID for typed entities, Name for zones since Handles regenerate) so the list survives across sessions. Ctrl+R opens a modal newest-first; stale entries (referenced entity deleted between sessions) render in danger-red and skip on click. ([#344](https://github.com/RydeTec/rcce2/pull/344))
- **World-state cache (perf)** — new `Modules/Loom/WorldCache.bb` holds cached aggregates (broken-ref count, 6 entity totals). Before: `Ribbon::recomputeCache` walked `O(actors * animsets + zones * portals * zones)` every frame. After: the same scan fires at most once per mutation (Composer commit/toggle/discard, EntityFactory create/delete, Palette picker commit invoke `WorldCache_Invalidate`); between mutations the per-frame ribbon paint is constant-time. Same recorder-facade pattern as Timeline / Recents (ADR 005). ([#346](https://github.com/RydeTec/rcce2/pull/346))
- **Save All (Ctrl+S) + save-on-exit prompt** — new `Modules/Loom/SaveAll.bb` dispatches `Composer::commitSaveForKind` for every dirty kind in one shortcut. Esc-exit-empty now intercepts when any kind is dirty and opens an `ExitPrompt` modal with Save All / Discard All / Cancel buttons; Esc inside the modal = Cancel (panic-press doesn't lose work). Without this a session with edits across four tabs needed four clicks, and Esc-exit silently discarded unsaved changes. ([#347](https://github.com/RydeTec/rcce2/pull/347))

Thickened card top accent from 1px → 3-line brass stack. Loaded Segoe UI as the body font with graceful fallback. New `LoomTheme_UseBody` / `LoomTheme_UseDisplay` font-swap helpers. Footer hint gains "F1 for shortcuts" so users can discover the cheat sheet without already knowing about it. ([#349](https://github.com/RydeTec/rcce2/pull/349))

- **Duplicate entity** — new `Dup` button on the composer action cluster (next to Delete) clones the focused entity via `EntityFactory_Duplicate`. Per-kind deep-copy helpers (`DuplicateActorTemplate` / `DuplicateItemTemplate` / `DuplicateSpellTemplate` / `DuplicateAnimSetTemplate`) live in the non-Strict data modules and handle the field-by-field copy including the Attributes side-instance deep-copy. Faction duplicate finds the next empty slot. Cloned entity gets " (copy)" appended to its primary name field and auto-focuses for immediate editing. - **Composer scroll** — entities with lots of fields (Actor with all its toggles + ints, Item with weapon+armour sections, Faction with many members, Zone with many portal links) previously had their bottom rows silently clipped by the panel height. Scroll resets on focus change. The previous "fit-cap" cutoffs on faction members / animset users / zone portal links are removed since scroll handles them. ([#354](https://github.com/RydeTec/rcce2/pull/354))
- **Responsive browser grid + collapsible composer** — Browser's card grid shrinks by `Composer::width()` so right-column cards aren't half-hidden behind the panel. Click `<` to expand, `>` to collapse. Mode persists across re-focuses. ([#355](https://github.com/RydeTec/rcce2/pull/355))
- **Drop shadows on cards + modals + atlas nodes** — new `LoomShadowCard(x, y, w, h)` primitive in `Theme.bb` paints a 2-layer fake (stone-900 at +2px, stone-950 at +4px). Wired into every Browser card (entity + tool), every modal (Palette / Timeline / Recents / BrokenRefs / ExitPrompt / Help), every Toast, and every Atlas node. Surfaces now read as physical tiles lifted off their background rather than printed-on labels. ([#356](https://github.com/RydeTec/recce2/pull/356))
- **Browser selection set** (bulk-edit foundation) — new `Type SelectedEntity` collection holds (kind, refID) pairs across kinds. Shift+Click a card adds/removes it from the selection; plain click clears + focuses (preserves the single-edit flow). Selected cards paint with a warning-orange border + brass-tinted fill. Browser footer hint updates to `"N selected | shift+click to add/remove | Esc to clear"` when non-empty. Esc priority chain extended: `modal > filter clear > selection clear > back stack > exit`. Bulk-edit composer view comes in the follow-up iteration. ([#357](https://github.com/RydeTec/recce2/pull/357))
- **Bulk-edit composer + bulk delete** — when Browser has a non-empty selection AND no single entity is focused, the composer renders a **warning-bordered bulk-edit panel** instead of nothing. Shows selection count, distinct-kinds summary ("actor, item"), scrollable list of every selected entity (with stale-entry detection), and a **Bulk Delete** button with arm/confirm. Confirmed click snapshots (kind, refID) pairs upfront (decouples the delete iteration from concurrent SelectedEntity mutation) then dispatches `EntityFactory_Delete` per entity; trailing toast summary so per-entity toasts don't spam.
- **Bulk field broadcast** — for **homogeneous selections** (all selected entities the same kind), the bulk-edit panel grows an "Apply to all" section with per-kind curated broadcast-safe field inputs: item gains Value/Mass/Damage/Armour, spell gains Recharge, actor gains XPMultiplier/Scale/Aggression/AggroRange/Faction, zone gains Gravity. Click input → type → click Apply broadcasts the value to every selected entity of that kind via the existing `Composer::writeField` dispatch, marks the kind dirty once, invalidates the world cache once, records a single rolled-up Timeline entry (`bulk-N → value`). Faction/animset show a `(no broadcast-safe fields)` row. Heterogeneous selections only show delete since cross-kind fields don't share semantics. Buffer preserved after commit so the user can re-apply quickly. Closes the design's "bump every weapon's damage by 10%" pitch.
- **Actor field coverage: attributes + resistances + 7 scalar gaps** — closes the single largest field-coverage gap vs GUE. The Actor composer now exposes: every defined entry in the project's 40-row **Attributes table** (HP / MP / Speed / Energy / etc) as a per-row [Value | Maximum] grid that walks `AttributeNames$()` and skips empty slots, every defined **Damage Resistance** (walks `DamageTypes$()` for labels, skips empty), plus seven previously-hidden scalar/toggle fields (Radius, Environment, InventorySlots, DefaultDamageType, TradeMode, PolyCollision) and Start Location ([StartArea | StartPortal]). New `doubleIntRow` + `miniEditCell` helpers for the side-by-side Value/Max grid layout (Blitz has no native two-column input row). `writeField` gains parametric branches matching the `attribute_value_<i>` / `attribute_max_<i>` / `resistance_<i>` fieldId pattern. Before this, the actor composer had ~9 editable fields; now it has 16 scalars + 40 attribute pairs + 19 resistances = up to **96 editable cells per actor**, fully covering everything a designer needs to tune combat / progression without dropping back to GUE.
- **Item field coverage: attributes + 11 hidden scalar/string fields** — mirrors the actor pass for items. The Item composer now exposes the 40-row Attributes table (Items use Attributes for equipped-bonuses — a sword adding +5 STR, armor adding +20 HP, a potion adding +10 Mana). New sections: **Consumable** (EatEffectsLength), **Visuals** (ThumbnailTexID, MMeshID, FMeshID, ImageID, plus 5 Gubbins[i] equip-slot activation toggles), **Misc** (MiscData free-form string). Weapon section grows with WeaponDamageType, RangedProjectile, RangedAnimation. `renderAttributesTable` refactored from Actor-specific to generic `(kind, refID, attrs.Attributes)` so a single helper serves both kinds. `writeField` item branch gains the same parametric `attribute_value_<i>` / `attribute_max_<i>` / `gubbin_<i>` patterns. With this, every primary `Type Item` field is now Loom-editable except the unused `ItemType` enum (composer shows it as a read-only Type label since changing item-type at runtime would invalidate the weapon/armour conditional sections).
- **Zone editor: portals + triggers + spawn points + weather** — closes the largest editing gap for zones. Before: Loom could edit Name/Outdoors/PvP/Gravity + entry/exit scripts + portal-link targets only. Now exposes: full portal editing (Name + Target + X/Y/Z/Size/Yaw, per portal sub-section), 150 script trigger slots (X/Y/Z/Size + Script/Method, per trigger sub-section walked from defined slots), 1000 spawn point slots (Actor chip + Waypoint + Size/Range + Frequency/Max + Script/ActorScript/DeathScript, walked from defined SpawnActor>0 slots), and the 4 weather-chance slots. Three new render helpers: `renderZonePortals` / `renderZoneTriggers` / `renderZoneSpawns`. `writeField` zone branch gains ~25 new parametric prefix patterns (portal_x_<i> / portal_y_<i> / portal_z_<i> / portal_size_<i> / portal_yaw_<i> / portal_name_<i>, trigger_x_<i> / trigger_y_<i> / trigger_z_<i> / trigger_size_<i> / trigger_script_<i> / trigger_method_<i>, spawn_actor_<i> / spawn_waypoint_<i> / spawn_size_<i> / spawn_range_<i> / spawn_freq_<i> / spawn_max_<i> / spawn_script_<i> / spawn_ascript_<i> / spawn_dscript_<i>, weather_<i>); careful prefix-ordering so specific patterns (portal_x_) get first crack before the generic catch (portal_) that was originally introduced for the picker. Spawn actor refs are clickable thread chips (right-click swap), so a designer can re-target a spawner without ever leaving the composer. Caveat: the 3D zone viewport for visual coord placement is still deferred (ADR 004) — these are text inputs, but anything you can author in GUE's properties sidebar is now Loom-editable.
- **AnimSet 150-slot clip editor + Spell thumbnail** — AnimSet previously had Name + back-references only. Now exposes the full 150-clip animation table: per-clip sub-section with Name (string), Start/End frames (side-by-side via `doubleIntRow`), and Speed (float). Each sub-section header shows the well-known animation name when applicable (Slot 149 → "Walk", Slot 141 → "Attack (default)", etc — covers all 29 `Anim_*` constants from `Animations.bb`). Slots that are both empty AND not well-known are skipped so designers see only the relevant clips rather than 150 blank entries. Spell composer gains the missing `ThumbnailTexID` field (icon-swap for the spellbook). `animSlotLabel$` helper for the constant-name lookup; `writeField` animset branch gains `clip_name_<i>` / `clip_start_<i>` / `clip_end_<i>` / `clip_speed_<i>` parametric patterns with careful prefix ordering. With this iteration, every primary field on every entity kind is Loom-editable.
- **Zone sub-entity add + delete (portals / triggers / spawns)** — full content authoring loop for zones. Each zone sub-section header (Portals / Triggers / Spawns) gains a "+ New" pill button that finds the first empty slot and seeds it with sensible defaults (portal: self-loop link, size=5; trigger: "New trigger" script, size=5; spawn: first defined actor as ref, size=5, range=100, freq=30s, max=1). Each existing sub-entity gets a tiny "x" delete button on its header row that zeros the defining field (PortalName, TriggerScript, SpawnActor) so the iteration skips it next frame. No arm/confirm on sub-entity delete (recoverable via the zone-level Discard) — that's reserved for whole-entity delete where the blast radius is bigger. New helpers: `addNewButton` / `subDeleteButton` (paint + hit-test in one call), `zoneAddPortal` / `zoneAddTrigger` / `zoneAddSpawn` (find empty slot + seed), `firstDefinedActorID` (default for new spawns). Section header now renders even when the section is empty so the "+ New" button is reachable from a fresh zone. Closes the last "but I can't actually build a new zone" gap.
- **Project Settings panel (Misc / Hosts / Other / Money .dat)** — project-level configuration that has NO editor surface in GUE either (hand-edited binary .dat) is now first-class in Loom. New "Settings" browser tab opens a singleton composer view exposing: Identity (Game name, Update URL, Music URL — Misc.dat), Hosts (Server host, Update host — Hosts.dat), Network/runtime (Server port, Hide nametags, No collisions, View mode, Require memorise — Other.dat), Speech bubbles (Use bubbles + RGB — Other.dat), Currency tiers (4 named tiers + 3 conversion multipliers — Money.dat). New `Modules/Loom/Settings.bb` (non-Strict — needed for SafeWriteOpen/Commit typing and the dim-write-from-Strict trap) owns: 22 `LoomCfg_*` globals, `Loom_LoadSettings` (tolerant of missing files — fresh projects don't have all four), `Loom_SaveSettings` (writes all four atomically via SafeWrite), `SettingsSaved` dirty flag (joins the per-kind dirty fleet), 21 `LoomSettings_Set*` non-Strict setters routed through `Composer::writeField` for kind="settings" since Strict methods can't write Globals directly. Wired into SaveAll (Ctrl+S), ExitPrompt (save-on-quit), Conscience Ribbon (dirty badge), Threads::lookupName ("Project Settings"). Closes a major workflow gap — designers can configure game-wide options without leaving Loom or hand-editing binary files.
- **Faction relations editor** — the 100×100 `FactionDefaultRatings` grid drives every actor's combat AI (0 = friendly, 1000 = hostile), but was previously invisible in Loom. The faction composer gains a "Relations (this → other)" section listing one editable int row per other defined faction. Edit fires through `SetFactionRelation` (new non-Strict setter in `Actors.bb` mirroring `SetFactionName` — Strict methods can't write the `Dim FactionDefaultRatings(99, 99)` directly). Existing `SaveFactions` already persists the relation grid, so no new save path needed — clicking Save on Factions writes the new relations alongside the names. Rating clamps 0..255 (matches the on-disk byte storage). The reverse direction (Y's view of X) is editable from Y's own composer view; each faction owns one direction of every relation, which mirrors how the data is stored.
- **Damage Types + Attribute Names catalogs in Settings tab** — completes the Settings panel with the two big project-level catalogs. New sections: **Damage Types** (20 named slots from `DamageTypes$` / `Damage.dat` — used by combat damage type lookups), **Attribute Assignment + Attributes catalog** (40 slots from `AttributeNames$` / `AttributeIsSkill` / `AttributeHidden` arrays + the `AttributeAssignment` global from `Attributes.dat` — each slot gets Name + Skill toggle + Hidden toggle sub-section). `Loom_SaveSettings` extended to write `Damage.dat` + `Attributes.dat` alongside the existing four files. New non-Strict setters in `Actors.bb` (`SetAttributeName`, `SetAttributeIsSkill`, `SetAttributeHidden`, `SetAttributeAssignment`) + `Items.bb` (`SetDamageTypeName`) per the dim-write-from-Strict trap pattern. New `SaveDamageTypes` function in `Items.bb` (didn't exist before — the file was previously write-only via hand-editing). With this, the Settings tab covers **everything project-level** that GUE doesn't have an editor for: server config, currency tiers, damage types, attribute schema.
- **Asset preview (texture thumbnails for Item + Spell)** — first cut of roadmap item #1. Item and Spell composers now render a 64×64 thumbnail next to the `ThumbnailTexID` field. New `Modules/Loom/ImageCache.bb` (non-Strict) provides `Loom_GetItemImage(ID)` (lazy load via `GetTextureName$` from Media.bb → strip trailing flag byte → `LoadImage("Data\\Textures\\<name>")` → cache in `ImageCacheSlots(65535)`) and `Loom_DrawImageScaled(ID, x, y, w, h)` (paints centered with aspect ratio, falls back to a stone-900 `?` placeholder for missing/invalid IDs). Path-traversal guard mirrors `Media.bb`'s `GetTexture` defense. `IMAGE_CACHE_MISS = -1` sentinel distinguishes "tried and failed" from "not tried yet" so failed loads don't retry every frame.
- **Browser-card thumbnails (Item + Spell)** — extends the iter-34 asset preview to the browser card grid. Every Item and Spell card gains a 32×32 thumbnail in its bottom-right corner. Designers scanning the grid recognize items by icon, not just name — the icon is often the fastest discriminator (especially when names are localized or terse, e.g. "Sword" vs "Sword [+1]" vs "Sword [+2]"). Uses the same `Loom_DrawImageScaled` from `ImageCache.bb`, so the cache stays warm across composer ↔ browser navigation. This closes the browser-thumbnail asset-preview gap; the remaining preview refinements are tracked separately below.
- **Validation rules — Issues modal (was Broken Refs)** — broadens the existing Broken Refs modal into a full Issues surface with six categories and three severity levels. New categories beyond broken refs: **empty-field** (Actor with no Race/Class, Item with no Name, Spell with no Name), **playability** (playable actor missing male/female anim set — character will T-pose), **weapon-config** (weapon with `WeaponDamage = 0` — decorative weapon), **spell-config** (spell with no Script bound — cast does nothing; item/spell with Script but no Method), **orphan-zone** (info-severity — zone with 0 portals, 0 spawns, 0 triggers — nothing for a player to do there). Each entry now has `Severity` (error/warning/info) and `Category` fields on `Type BrokenRef`; rows render a color-coded 4px left rail (red error / orange warning / arcane-blue info) and matching field-value text. Title changes from "BROKEN REFERENCES" → "ISSUES"; empty-state copy from "no broken references" → "no issues". Conscience Ribbon chip label grows "+ issues" suffix when broken refs > 0, and the "no broken refs" state is now click-through so users can open the modal to see warning/info issues that don't count toward the headline number. New `BrokenRefs::emitFull` helper for the 8-arg shape; legacy `emit` defaults to `severity="error"` / `category="broken-ref"` for back-compat.
- **Responsiveness hotfix (icon scaling + MouseHit drain)** — two user-reported bugs from a screenshot of the Loom Spell tab. Bug 1: thumbnails painted at native image size (a fireball texture exploded across the whole screen) because Blitz3D's `DrawImage` doesn't scale; iter 34 incorrectly assumed it clipped to the dest rect. Fix: per-size cached `CopyImage`+`ScaleImage`'d handles (`ImageCacheSmall(65535)` for 32×32 + `ImageCacheLarge(65535)` for 64×64) with explicit-size API (`Loom_DrawThumbnailSmall` / `Loom_DrawThumbnailLarge`). Plus per-frame load budget (`LOOM_IMAGE_LOADS_PER_FRAME = 3`) so a tab with many uncached cards doesn't freeze the first frame; cache warms over ~30 frames. Bug 2: "have to click 3 times for it to register" — `MouseHit(b)` is read-and-clear in Blitz3D and Browser ran first in `renderFrame`, draining every click before Composer / Ribbon / modals could see it. Fix: capture `MouseHit(1)` + `MouseHit(2)` once per frame in `Loom_BeginFrame()`; expose via `Loom_MouseClicked()` / `Loom_MouseRightClicked()` accessors; replaced 11 per-surface call sites across 10 files. ## Deferred (with reasons — read before reopening)

### Literal 3D zone viewport — no longer deferred (shipped via ADR-004 Phases A-C)

**Original reason for deferral (resolved):** `ClientAreas.bb`'s `LoadArea` was entangled with GUE-specific UI globals — `GY_Cam`, `GY_CreateProgressBar`, `ResolutionType`, `RandomImages`, `GetMusicName$`, `GetTexture`, `GetFilename$` (which lived inside `GUE.bb` itself, not in a shared module). The ADR-004 phased refactor dissolved that entanglement.

**Path to unblocking:** Either (a) extract the data-only parts of `LoadArea` into a new `Modules/AreaMeshLoader.bb` that both GUE and Loom can call, or (b) write a Loom-side mesh loader that parses the same `.dat` format independently. (a) is correct, (b) risks drift. Either is a meaningful refactor — probably needs to be its own multi-PR project before Loom can pick it up.

**Status: SHIPPED.** All three ADR-004 phases are merged: Phase A (shared `Path.bb`, PR #429), Phase B (data-only `Modules/AreaLoader.bb`, PR #547), and Phase C — the zone viewport's **world mode**: a toggle pill loads the focused zone's real terrain/scenery/water via `LoadAreaData` and overlays the schematic markers at their true coordinates, soft-failing back to schematic when a zone has no visual `.dat`.

**World-mode entity editing — SHIPPED** (ADR-004 Phase C follow-up). The add / drag-move / delete edit ops now work in world mode against the real rendered terrain, not just the schematic floor plane. New shared `Loom_PickGround` helper in `ZoneViewport.bb` resolves mouse coords to a placement point that lands on `VPGround` (the flat editor floor) in schematic mode and on the zone's real terrain / scenery (`EntityPickMode`-eligible geometry loaded by `LoadAreaData`) in world mode; the portal-add (Shift+LMB), trigger-add (Shift+RMB), spawn-add (Shift+MMB), Ctrl+LMB delete, and RMB drag-move handlers all route through it. Newly-placed entities land at the picked terrain height via `Loom_PlaceY#` (schematic keeps Y=0). The old world-mode read-only gates on marker-drag + delete are removed. Writes go through the same `Ar\Portal*/Trigger*/Waypoint*` fields the schematic editor already used and persist through GUE's `ServerSaveArea` serializer — no new save path, no format drift.

**World-mode scenery mesh placement — SHIPPED** (ADR-007). Add / move / delete / select for scenery mesh instances directly on the loaded terrain, scoped to world mode (scenery is visual world data, not schematic gameplay data). An **"add scenery"** pill opens a `MeshCatalog` picker; arm a mesh brush, then LMB the terrain to drop an instance (reuses `Loom_PickGround`). Move is an RMB terrain-drag (Shift+RMB = height); delete is Ctrl+LMB; select is LMB → a small property readout (mesh id / pos / yaw / scale). Every field `SaveArea` serializes is initialized on add (mesh id, XYZ, pitch/yaw/roll, scale, anim mode, scenery id, texture id, catch-rain, collision type, lightmap, RCTE, cast/receive shadow, render range); the **engine** mesh id is written, not a catalog index. Two safety guardrails (see ADR 007): `SaveArea` was relocated verbatim from `ClientAreas.bb` into the shared `Modules/AreaLoader.bb` (Phase D) so Loom can reach it, and persistence uses a **separate `SceneryDirty` flag** (never the shared `ZoneSaved`) through `Loom_SaveScenery`, which is **gated on `VPWorldLoaded`** — the whole-visual-area `SaveArea` can never run against an unloaded world (no-op + warning toast otherwise). Unsaved scenery edits are warned + discarded on world unload.

**Explicitly still deferred** (separate large subsystems, not attempted): terrain heightmap sculpting, water-volume editing, weather/environment sub-tabs, and a distinct scenery-**texture**-paint surface (if it turns out to be separate from mesh placement). The prior Y-mode marker-lift inflation is fixed: marker visual lifts remain render-only, so vertical drags persist semantic Area Y in both schematic and world mode.

See [decisions/004-deferred-3d-viewport.md](decisions/004-deferred-3d-viewport.md) and [decisions/007-world-mode-scenery-editing.md](decisions/007-world-mode-scenery-editing.md) for full context.

### Walk-in playtest

**Reason:** The design called for "spawn into the zone as a player without restarting the server." This requires a live server bridge — Loom would have to either (a) speak the wire protocol to a running `Server.exe` to inject a player, or (b) embed a server in-process. (b) is huge. (a) needs the wire protocol stable and a way for the server to accept "spawn this account at this position" out of band, which it doesn't today.

**Path to unblocking:** server-side feature work, not Loom work. Out of scope until a Server.exe admin/test API exists.

### Multi-cursor / collaboration

**Reason:** The design's aspirational story included "two designers in the same world." This is months of work (sync protocol, conflict resolution, presence indicators) and the rcce2 user base is currently solo or small async teams.

**Path to unblocking:** out of scope indefinitely.

### Inheritance / templating for entities ("base goblin + 3 variants")

**Reason:** The design called for "change the base goblin's run animation and all three variants update." This needs a real entity-inheritance model in the data format, which rcce2 doesn't have. Today, every NPC is a flat record.

**Path to unblocking:** data-format change in the engine. Loom can't add this unilaterally.

## Decision-making

When adding to the roadmap or repositioning items, the rough priority signals are:

1. **Does it surface content the user already has?** (Browser pivot was high-priority for this reason — alpha was hiding the project's content.)
2. **Does it unlock a real workflow?** Hero flows: "tune a spell," "find a broken reference," "see what uses this faction."
3. **Does it match the design north star?** (Threads, search, walk-in.) Or is it scope creep into things the design didn't call for?
4. **What's the unblock cost?** A small change with infrastructure dependencies (editing → dirty tracking → save) is cheap-looking but expensive. Quote the dependency.
